# WAX&THINK サンプル系記事の事実チェック恒久ルール

新規記事・コラムを追加／既存を編集するとき、サンプル・年・アルバム・客演・チャート
順位・曲の実在性に関する事実主張は、生成時のハルシネーションを前提に必ず一次ソースで
裏取りする。記事を「残す/正しい」前提で都合よく解釈しない。

## 一次ソースの優先順位
1. サンプル元（曲名・原曲アーティスト・原曲年・収録アルバム）: WhoSampled
2. リリース年・アルバム・客演・チャート順位・トラックリスト: Wikipedia + Discogs
3. 歌詞・客演表記・スクラッチ元フレーズ: Genius

※ Last.fm / songtell / 個人ブログ / AI生成解説サイトは根拠にしない（補助のみ）

## 必ず疑うフィールド（過去に実際に誤りが出た箇所）
- 曲の実在性・収録アルバム（公式トラックリストに無い曲が生成された実例あり＝bodega疑い）
- サンプル元の曲名・年（実在しないサンプルを複数捏造した実例あり＝Werdz）
- サンプルの楽器の誤り（ホーン→実はギター、ドラム→実はピアノの取り違えの実例あり）
- スクラッチ元フレーズの出典（別曲のバースを誤帰属した実例あり＝F.A.L.A.→実はDWYCK）
- リリース年とアルバム名のペア
- チャート順位（Billboard 200とR&B/Hip-Hopチャートの混同。両方を区別して記載）
- 内部リンクのslugと曲名の一致

## 必ず疑うフィールド（サンプル系以外で過去に誤りが出た箇所）
- 「初/唯一/最初」の断定（デビューシングル・初出・唯一の例）。例外がいないか確認してから書く。
  実例: 「Juicy はデビューシングル」は誤り → デビュー*アルバム*『Ready to Die』のリードシングル（デビューシングルは1993年「Party and Bullshit」）。"first single from his debut album" を「デビューシングル」と誤読しやすい。
- 客演・コーラス担当者を、同レーベル/同時期の近い別人と取り違える。クレジットは曲単位で確認。
  実例: The Food のコーラスを John Legend と誤記 → 正しくは Kanye West（同じGOOD Music所属で混同）。
- 存在の否定の断定（「公式MVは存在しない」等）。"無い"は"有る"より裏取りが難しいので特に慎重に。
  実例: 「Triumph に公式MVは無い」は誤り → Brett Ratner監督の公式MVが実在。
- サンプルの誤転記（同じアーティストの別曲のサンプルが混入）。songs.ts編集時、隣の曲のフィールドと混ざっていないか確認。
  実例: nas-is-like のサンプルに N.Y. State of Mind のサンプル（Joe Chambers "Mind Rain"）が誤って入っていた。
- コラムで語の「語源・元義」を断定しない（語源は俗説が多い）。記事の趣旨が語源学でないなら用法説明に絞る。
  実例: dope/hustle の語源断定（実際はオランダ語起源）、flow の語源を AAVE概念とするのは俗説。

## 記述ルール
- 裏が取れた事実だけ断定で書く。取れないものは載せない（「諸説あり」で逃げない）。
- サンプルは楽器・原曲名・原曲年まで具体化（「ジャズのホーン」等の曖昧表現は禁止）。
- チャート順位は「どのチャートで何位か」を必ず明記（「全米◯位」等の曖昧表記は禁止）。
- サンプル年は WhoSampled のオリジナル収録表記を一次根拠（再発・コンピ・映画使用で
  年が割れるため。Coffee Cold=1966が確定した実例あり）。
- 人物の経歴で年表記が資料間で揺れる場合は、断定せず年を外すか出典を1つに固定。

## 作業フロー（毎回）
1. 事実主張を箇条書きで列挙
2. 各項目を一次ソースで照合（ソースURLを記録）
3. 検証結果を一覧報告（OK / 要修正 / 確証なし / 完全に虚偽）
4. 曲の実在自体が怪しい場合は、修正前に (a)事実修正で残す (b)大幅書き換え
   (c)記事ごと削除/非公開 の3択を根拠付きで提示し推奨を1つ示す
5. 修正案提示 → 承認 → 適用 → build → grep残存チェック → 承認後push
6. 記事を削除する場合は、内部リンク（relatedSongs等）からの参照も洗い出してリンク切れ対策

## 歌詞引用ルール（スラング種別で要否判断）
基本方針: 引用は解説に必要な最小限の断片のみ。スラングの種類で引用の要否を判断する。

### 引用不要（語・意味・背景の説明だけで完結させる）
- **ブランド固有名詞系**（Lo goose、Shaolin 等）: 何を指すかを説明すれば足りる。
- **地域隠語**（Jakes、base 等）: 語と意味と土地背景の説明で完結。
- **思想・文化語彙**（Old Earth 等）: 概念の解説で完結。
→ これらは歌詞行を引かず、語と意味と背景だけで書く。

### 引用必要（1〜2行の最小断片を引く）
- **韻・言葉遊び**（crime side / Times side、keys / seas 等）: 音の対応を示すため最小断片が要る。
- **AAVE文法現象**（here go、コピュラ省略 等）: 実際の語順・省略を見せる必要がある。
- **トリプルエンタンドル**（G off 等）: 多義の重なりを原文で示す必要がある。
→ 解説に必要な1〜2行のみを引く。

### 引用量の上限
- 1ユニットあたり引用は1〜2行まで。
- 1曲全体で、引用行が連続して歌詞の骨格を形成しないこと。
- pre-pushの [D] eng引用率60%未満の精神を常に維持する。
- [D]の母数には、折りたたみ用例スロット（slot="usage"／「語法 — どう使うか」）内の英語も引用として含める。

### 引用予算の運用（[D]<60%を書きながら管理する・2026-07-03確定）
nas-is-like増補（29unit・[D]59%）で確立した手順。25〜30unitの量産と[D]<60%は、引用の
「予算配分」を書きながら管理しないと両立しない。

- **[D]の仕組み**: 母数＝Genius歌詞の重複除去済み行（**3回以上繰り返す行＝コーラス等は母数から除外**）。
  分子＝eng＋usageスロットの英語が部分一致（行内の単語の60%以上を含む）でカバーする行数。
- **手順**: unitを数個書くごとに `node agent/src/check-lyrics-coverage.mjs {slug}` を回す。
  [D]が57%を超えたら、以降のunitは上記「引用不要」方式（行を引かず、見出しに表現＋本文で
  位置の言及と語の解説＋▶頭出しリンクで完結）に切り替える。
- **コーラス行は引用自由**: 3回以上反復する行は[D]の母数外なので、引用しても[D]が動かない。
  フック・コーラスの学習unitはここを使う。
- **usageスロットも[D]に算入される**: 語法欄の英語例文は、歌詞行と語彙がかぶらない短文にする
  （部分一致判定のため、歌詞行の単語を6割以上含む例文を書くと当該行が「引用済み」扱いになる）。
- **既に引用した行の再利用は無料**: 同じ行を別unitで再引用しても[D]は増えない
  （例: nas-is-like の street-sweeper と greeks-egypt は同じ行を共有）。
- 実例: nas-is-like ＝ 引用あり20unit＋引用不要9unit で [D]59%。
